# Milestones — תוכנית בנייה

> אבני הדרך המרכזיות לפיתוח משחק Simon, לפי סדר הבנייה, בהתבסס על PRD.md, ARCHITECTURE.md ו-DESIGN.md.
>
> החלוקה היא ל-**Vertical Slices**: כל Milestone מוסיף יכולת משתמש שלמה שעובדת מקצה לקצה. Milestone 1 הוא Milestone ההקמה, שהוא תנאי מקדים לכל השאר.
>
> לפי ARCHITECTURE.md, לפרויקט אין Backend, Database או Supabase. לכן אין סביבות מסד נתונים נפרדות ואין Database Migrations. Production הוא האתר הסטטי ב-GitHub Pages, והוא מוקם ב-Milestone 4.

## כללי ביצוע הפיתוח – Development Execution Rules
- יש לפתח את ה-Milestones לפי הסדר שהוגדר במסמך.
- לאחר השלמת כל Milestone, יש לעצור את הפיתוח ולהציג למשתמש את התוצר שהושלם ואת תוצאות הבדיקות מול ה-Definition of Done.
- המשתמש בודק את התוצר בעצמו ומבקש תיקונים במידת הצורך.
- אין להתחיל בפיתוח ה-Milestone הבא ללא אישור מפורש של המשתמש — בקשה לדחוף את השינויים ל-GitHub, או אישור מפורש.

> סימוני התקדמות ליד כותרת ה-Milestone (Claude מוסיף אותם; הכללים נמצאים ב-CLAUDE.md): 🟡 = נבנה, ממתין לאישור · ✅ = אושר.

---

## Milestone 1 — הקמת הפרויקט ומסך הבית המעוצב
- **מטרה:** להקים את תשתית הפרויקט ולהציג את מסך הבית כפי שהוא מופיע ב-Mockups, כך שהאפליקציה רצה מקומית ומשמשת בסיס לשאר אבני הדרך.
- **מה יש לממש:**
  - פרויקט Vite + TypeScript (Vanilla, ללא Framework), עם Vitest מוגדר ופקודות `dev`, `build` ו-`test`, במבנה התיקיות שמוצע ב-ARCHITECTURE.md (`src/ui`, `src/game`, `src/audio`, `src/styles`, `tests`).
  - קובץ CSS בסיסי עם ה-Tokens של ה-Style Guide: צבעים, טיפוגרפיה, רדיוסים ומרווחים.
  - הגופן Rubik כלול בקובצי הפרויקט עצמם, ולא נטען משירות חיצוני, כדי שיעבוד גם Offline בהמשך.
  - מסך הבית לפי DESIGN.md: שורת כותרת «סימון» / «משחק זיכרון קלאסי», לוח ארבעת הצבעים עם ה-Hub, כפתור «התחל», קו Divider וקישור «אודות» עם אייקון.
  - `index.html` עם `lang="he"` ו-`dir="rtl"`, ופריסת Mobile-first.
  - בדיקת Vitest פשוטה אחת שעוברת, כדי לוודא שתשתית הבדיקות עובדת.
  - עדכון «פקודות הרצה» ב-CLAUDE.md.
- **תוצר מצופה:** האפליקציה רצה מקומית ומציגה את מסך הבית המעוצב בעברית. הכפתורים עדיין לא מפעילים משחק.
- **Definition of Done:**
  - `npm run dev` מפעיל את האפליקציה, והיא נפתחת בדפדפן ללא שגיאות ב-Console.
  - `npm run build` ו-`npm run test` מסתיימים בהצלחה.
  - מסך הבית תואם ל-Mockups במבנה, בצבעים, בגופן ובכיווניות RTL.
  - ברוחב מסך טלפון (כ-375px) המסך מוצג במלואו, ללא גלילה אופקית.

## Milestone 2 — משחק מלא במסך הבית
- **מטרה:** לאפשר לשחק משחק Simon שלם מתחילתו ועד סופו — מלחיצה על «התחל» ועד ניצחון או כישלון, והתחלה מחדש.
- **מה יש לממש:**
  - **Game Engine** (מודול לוגיקה ללא תלות ב-DOM או בשמע): רצף אקראי, הוספת צבע בכל שלב, בדיקת קלט לפי הסדר, נקודה אחת לכל לחיצה נכונה, סיום מיד בלחיצה שגויה, ניצחון אחרי שלב 10, המצבים `ready` / `showing-sequence` / `awaiting-input` / `won` / `lost`, ומהירות הצגה שעולה עד גבול קבוע.
  - **Audio Module** (Web Audio API): צליל שונה לכל צבע; הפעלת `AudioContext` מתוך הלחיצה על «התחל»; אם השמע נכשל, המשחק ממשיך עם חיווי חזותי בלבד.
  - **חיבור לממשק:** הצגת הרצף במצב Lit של אזורי הצבע, קלט מגע, נעילת אזורי הצבע (מצב Locked) בזמן הצגת הרצף, הצגת מצב המשחק, ובסיום — הודעת ניצחון או כישלון, ניקוד סופי וכפתור «התחל מחדש», ברכיבי ה-Style Guide.
  - **בדיקות Vitest** ללוגיקת המשחק, לפי הרשימה בסעיף 2.9 של ARCHITECTURE.md (מלבד השהיה, שמגיעה ב-Milestone 3).
- **פרטים פתוחים שיש לסגור עם המשתמש בשלב התכנון** (לא הוגדרו במסמכים): הנוסח של הודעות ההצלחה, הכישלון והניצחון; מיקום מצב המשחק והודעת הסיום במסך הבית; ערכי מהירות ההצגה והגבול שלה.
- **תוצר מצופה:** אפשר לשחק במסך הבית משחק מלא עם צבעים וצלילים, לראות הודעת סיום וניקוד, ולהתחיל משחק חדש.
- **Definition of Done:**
  - לחיצה על «התחל» מציגה צבע אקראי אחד עם תאורה וצליל; בכל שלב מוצלח נוסף צבע אחד לסוף הרצף הקודם.
  - בזמן הצגת הרצף, לחיצה על אזורי הצבע לא נקלטת.
  - כל לחיצה נכונה מוסיפה נקודה אחת; לחיצה שגויה מסיימת את המשחק מיד ומציגה הודעת כישלון, ניקוד סופי וכפתור «התחל מחדש».
  - השלמת שלב 10 מסיימת את המשחק בניצחון, עם הודעה, ניקוד סופי (55) וכפתור «התחל מחדש»; לא נוסף שלב 11.
  - «התחל מחדש» מאפס את המשחק ומתחיל משחק חדש.
  - מהירות הצגת הרצף עולה בין השלבים עד הגבול שנקבע, ואחריו נשארת קבועה.
  - כשהשמע חסום או מושתק, המשחק ממשיך לעבוד עם החיווי החזותי.
  - רענון הדף באמצע משחק מחזיר את מסך הבית למצב ההתחלתי.
  - כל בדיקות Vitest עוברות, ו-`npm run build` מצליח.

## Milestone 3 — מסך אודות, השהיה ותוצאה אחרונה
- **מטרה:** להוסיף את מסך «אודות» עם ההוראות, הסבר הצבעים והצלילים ותוצאת המשחק האחרון, ולאפשר לעבור אליו באמצע משחק ולחזור בלי לאבד את ההתקדמות.
- **מה יש לממש:**
  - מסך «אודות» לפי DESIGN.md ו-Mockups: Top bar עם חץ חזרה, כותרת ותיאור, «איך לשחק?» עם ארבעת הצעדים, «ארבעת הצבעים והצלילים», כרטיס הניקוד וכפתור «חזרה למשחק».
  - ניווט בין שני המסכים: קישור «אודות» במסך הבית; «חזרה למשחק» והחץ במסך אודות.
  - שמירת `lastCompletedScore` ו-`lastResult` בזיכרון בלבד, עם «אין עדיין תוצאה» כשאין עדיין תוצאה.
  - השהיה במעבר למסך «אודות» (מצב `paused`: עצירת timers ושמירת השלב, הרצף ומיקום הקלט), והמשך מאותה נקודה בחזרה למסך הבית.
  - בדיקות Vitest להשהיה ולהמשך.
- **תוצר מצופה:** אפשר לעבור בין מסך הבית למסך אודות בכל רגע, לקרוא את ההוראות, לראות את תוצאת המשחק האחרון ולחזור למשחק המושהה.
- **Definition of Done:**
  - מסך אודות תואם ל-Mockups במבנה, בתוכן, בעיצוב וב-RTL.
  - לפני שהסתיים משחק ראשון, כרטיס הניקוד מציג «אין עדיין תוצאה».
  - אחרי שמשחק מסתיים (בניצחון או בכישלון), מסך אודות מציג את הניקוד הסופי שלו.
  - הניקוד של משחק שעדיין פעיל אינו מחליף את התוצאה שמוצגת במסך אודות.
  - מעבר לאודות באמצע הצגת רצף או באמצע קלט, ואז «חזרה למשחק», ממשיכים את המשחק מאותה נקודה, בלי לדלג על שלב ובלי להוסיף נקודות.
  - רענון הדף מאפס גם את התוצאה האחרונה.
  - כל בדיקות Vitest עוברות, ו-`npm run build` מצליח.

## Milestone 4 — PWA, Offline ופריסה ל-GitHub Pages
- **מטרה:** להפוך את המשחק לאפליקציה שאפשר להתקין בטלפון ולשחק בה בלי אינטרנט, ולפרסם אותה באתר ציבורי ב-GitHub Pages.
- **מה יש לממש:**
  - `vite-plugin-pwa`: Web App Manifest (שם, `lang="he"`, `dir="rtl"`, צבעי מעטפת מה-Style Guide), אייקונים, ו-Service Worker ששומר מראש את כל הקבצים שהאפליקציה צריכה, כולל הגופן.
  - מדיניות עדכון מפורשת ל-Service Worker, כדי שגרסה חדשה לא תתערבב עם גרסה שמורה ישנה.
  - הגדרת `base` של Vite לנתיב ה-Repository ב-GitHub Pages.
  - GitHub Actions Workflow (`deploy.yml`): `npm ci`, בדיקות, Build ופרסום של `dist/`. אם הבדיקות או ה-Build נכשלים, הגרסה לא מתפרסמת. הרשאות `GITHUB_TOKEN` מצומצמות, וה-Actions מקובעים לגרסאות.
  - הדרכה של המשתמש, צעד אחר צעד, בהפעלת GitHub Pages עם GitHub Actions כמקור הפרסום ובווידוא ש-HTTPS מופעל. ה-push מתבצע רק באישור המשתמש.
- **תוצר מצופה:** המשחק זמין בכתובת ציבורית ב-GitHub Pages, אפשר להתקין אותו בטלפון כ-PWA, והוא עובד בלי חיבור לאינטרנט אחרי הטעינה הראשונה.
- **Definition of Done:**
  - Push לענף הראשי מפעיל את ה-Workflow; הבדיקות וה-Build עוברים, והאתר מתפרסם ב-GitHub Pages דרך HTTPS.
  - Workflow שהבדיקות שלו נכשלות לא מפרסם גרסה.
  - האתר שפורסם עובד תחת נתיב ה-Repository: הקבצים, ה-Manifest וה-Service Worker נטענים ללא שגיאות 404.
  - בטלפון (Chrome ל-Android ו/או Safari ל-iOS) אפשר להוסיף את האפליקציה למסך הבית, והיא נפתחת עם השם והאייקון שלה.
  - אחרי טעינה ראשונה, ניתוק האינטרנט ופתיחה מחדש — המשחק נפתח ופועל במלואו, כולל הגופן והשמע.
  - אחרי פרסום גרסה חדשה, האפליקציה המותקנת עוברת לגרסה החדשה לפי מדיניות העדכון שנקבעה, בלי שגיאות.
  - כל מה שהוגדר ב-Milestones 1–3 עדיין עובד בגרסה שפורסמה.
